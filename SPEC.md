# SPEC — приложение «Система»

Этот файл — единственный источник правды по проекту. Перед любой работой прочитай его целиком.
Работай только над текущим этапом (см. `STAGES.md`). Не реализуй функции будущих этапов, но
закладывай под них интерфейсы и места в архитектуре.

---

## 1. Что это

Личное приложение-«Система» в стиле RPG-интерфейса: превращает весь день пользователя в квесты.
Расписание, сон, вода, еда, учёба, тренировки, уход за собой, прогулки, финансы и обучение новому —
всё это квесты с наградами (баллы, опыт, характеристики) и штрафами. С пользователем общается
ИИ-персонаж, который ходит по экрану приложения, говорит голосом, хвалит и ругает.

- Платформы: **iOS и Android**, одна кодовая база.
- Языки интерфейса: **русский** (основной) и **турецкий**. ИИ и голос тоже на обоих языках.
- Пользователь пока один (владелец), но архитектура многопользовательская (позже — родственники).
- Работает **офлайн**, синхронизируется с сервером при появлении сети.

## 2. Стек

### Клиент
- **Flutter** (последняя стабильная), Dart, null-safety.
- Состояние: **Riverpod**. Навигация: **go_router**.
- Локальная БД: **Drift** (SQLite). Это основное хранилище; сервер — синхронизация и тяжёлые задачи.
- Локализация: `flutter_localizations` + ARB (`ru`, `tr`), ни одной строки UI в коде.
- Нативный код только там, где нет плагина (список в §12), через платформенные каналы.

### Сервер
- **Go** (последняя стабильная), **SQLite** (`modernc.org/sqlite`, без CGO), один бинарник.
- Debian, **1 ГБ RAM** — следи за памятью (без тяжёлых зависимостей, стриминг файлов, лимиты).
- Отдельный сервис рядом с уже работающими на сервере. **Ничего существующего на сервере не трогать**:
  свой системный пользователь, своя папка (`/opt/sistema`), свой порт, свой systemd-юнит.
- Доступ по HTTPS: бесплатный поддомен (DuckDNS) + Let's Encrypt через Caddy **только если порт 443
  свободен**; иначе — спросить пользователя, прежде чем трогать reverse-proxy.
- Диск 3 ТБ: фото храним как файлы, в БД только метаданные.

### CI/CD (Mac у пользователя нет)
- GitHub Actions:
  - **iOS**: `macos-latest`, `flutter build ipa --no-codesign` → упаковать `Payload/` в `.ipa` → artifact.
  - **Android**: `ubuntu-latest`, `flutter build apk --release`, подпись своим keystore из GitHub Secrets.
  - **Server**: `ubuntu-latest`, `go test ./...` + сборка `linux/amd64` бинарника → artifact.
- iOS-сборку запускать только на push в `main` и вручную (минуты macOS дорогие); Android и сервер — на каждый push.
- Секреты (ключи ИИ, пароли) **никогда** в репозитории. Только на сервере (`.env`) и в GitHub Secrets.

## 3. Установка на iPhone и проверенные ограничения

Приложение ставится на iPhone 15 Pro (iOS 26.6) через **Sideloadly с бесплатным Apple ID**.
Это проверено отдельным тестовым приложением. Итоги теста — обязательные ограничения:

| Возможность | iOS (бесплатный Apple ID) | Решение |
|---|---|---|
| Локальные уведомления, повтор каждые 60 с, кнопки действий | ✅ | основа всех напоминаний |
| Шаги/дистанция/этажи (CoreMotion) | ✅ | источник шагов на iOS |
| HealthKit | ❌ | не использовать на iOS; код за флагом `healthKitEnabled=false` |
| Геолокация «Всегда» + фоновые обновления | ✅ | прогулки |
| MapKit пешие маршруты | ✅ | маршруты на iOS |
| Голос поверх музыки с приглушением (duckOthers) | ✅ | подсказки на прогулке, голос персонажа |
| Now Playing Apple Music | ✅ | показ трека |
| Remote push (APNs) | ❌ | см. §9 «Сообщения ИИ» |
| Live Activity, виджеты (App Group), App Intents, URL-схема, Keychain, камера, сканер штрихкодов | ✅ | используем |
| AlarmKit | авторизация ✅, планирование не проверено | будильник-квест с фолбэком на уведомления |
| Блокировка других приложений (Screen Time) | ❌ | iOS: автоматизация «Команд», см. §8.6 |

- Профиль подписи живёт **7 дней** → в приложении баннер «Сертификат истекает через N дн.»
  (дата истечения берётся из embedded.mobileprovision) + напоминание переустановить.
- Все данные пользователя должны переживать переустановку: регулярная синхронизация с сервером
  + ручной экспорт/импорт JSON.
- На Android ограничений нет: FCM push, HealthConnect, блокировка приложений, будильники, оверлей.

Фичи, недоступные на платформе, **скрываются**, а не ломаются: единый `CapabilityService`, который
сообщает, что доступно на устройстве, и UI под него подстраивается.

Стиль — **«системное окно» из RPG**: тёмный фон, светящиеся голубые панели, ощущение
голографического интерфейса. Всё оригинальное: никаких чужих логотипов, названий, персонажей, ассетов.

- Цвета панели меняются по смыслу: штрафы — красная тема, награды — золотая, боссы — фиолетовая.
- Системные сообщения оформлены как «[ Уведомление ]», «[ Предупреждение ]», «Квест провален».
- Анимации: появление окна (масштаб 0.96→1 + прозрачность + «скан» сверху вниз 250 мс), пульс
  индикаторов, плавное заполнение шкал, частицы при получении уровня. Уважать «Уменьшение движения».
- Доступность: кнопки ≥44px, контраст текста ≥4.5:1, подписи для иконок, поддержка крупного шрифта.
- Иконки — линейные (stroke 1.7), один набор на всё приложение. Без эмодзи.
- Тема одна (тёмная).

4. **Следующий квест** (золотая тема): кольцо-таймер, название, награда/штраф, кнопки

6. **Ежедневные квесты**: чекбоксы, время, подзадачи, прогресс-бары, просроченные красным, итоговый штраф.
7. **Босс недели** (фиолетовая тема): цель, прогресс, таймер, награда и титул.
8. Мини-сводки: калории (съедено/сожжено/дефицит) и финансы (траты на еду/лимит/до стипендии).
9. **Ассистент**: персонаж + реплика с голосовой волной + микрофон + «Ответить…».
10. Нижняя навигация: Статус · Квесты · Питание · Магазин · Ещё.
    **Решение владельца (2026-10-22):** структура навигации пересматривается — аудит всех экранов и
    действий, новая схема нижней навигации/вкладок/«Ещё»/настроек согласуется с владельцем ДО

**Уточнение (решение владельца, 2026-10-21): вкладка «Статус» короткая.** На ней остаются только п.1–5
(шапка, сжатый статус, эффекты, следующий квест, лента дня). Ежедневные квесты и босс недели — во вкладке
«Квесты»; сводка калорий — в «Питании»; сводка финансов — в «Ещё»; ассистент — не панель, а персонаж
поверх всех экранов (§9.2).

## 5. Онбординг — максимально подробный

Первый запуск. Система собирает **всё**, что нужно для качественного плана. Оформлено как
«[ Уведомление ] Вы получили право стать Игроком…», дальше этапы с прогрессом.
Можно прерваться и продолжить; всё сохраняется сразу. Любой этап потом редактируется в настройках.
**Порядок показа (решение владельца, доработка 1.2):** Профиль → Персонаж и голос (п.11) → Тело → Фото тела → …
— ассистента выбирают в самом начале, и фото-сессии ведёт уже его голосом (на экране съёмки виден он сам).

1. **Профиль**: имя, язык, пол, дата рождения, часовой пояс, город (для погоды/магазинов). Часовой пояс по
   умолчанию — текущий пояс телефона; при вводе города подставляется по городу (встроенный справочник
   городов РФ и Турции, офлайн); можно выбрать вручную.
2. **Тело**: рост, вес, уровень активности, рабочая/сидячая нагрузка. Обхваты (талия, бёдра, грудь, шея, рука) —
   **необязательно**, «если знаешь»: иначе их примерно оценит ИИ по фото с учётом роста и сообщит пользователю.
3. **Фото тела** (спереди, сбоку, сзади) — **съёмка под руководством Системы, без нажатий**: человек ставит
   телефон, ассистент голосом и текстом говорит «отойди на ~2 м, подойди или отступи, чтобы совпасть с контуром», идёт обратный отсчёт
   (3/5/10 с, звук), снимок, «снимок сделан, повернись боком» — и так все ракурсы подряд. Фронтальная камера
   по умолчанию (видно себя и контур), снимки сохраняются незеркальными; можно переключить на основную,
   если снимает другой человек. Контурная подсказка поверх камеры (тело — ~75% высоты кадра; лицо — простой
   овал для анфаса и профилей, без нарисованного лица).
   ИИ даёт **оценку** % жира, мышечной массы, осанки, типа фигуры, отёчности лица.
   Всегда показывать «≈», диапазон и пометку «оценка по фото, не медицинское измерение».
   Пользователь может подтвердить/исправить, если знает точные цифры (например с умных весов).
4. **Кожа**: фото лица (анфас, профиль слева/справа, крупно проблемные зоны) + опрос
   (жирность к обеду, стянутость, реакции на средства, текущий уход). ИИ определяет тип кожи и
   **оценивает** выраженность акне/чёрных точек/постакне по простой шкале, тоже как оценку.
   При выраженных воспалениях — рекомендация показаться дерматологу.
5. **Здоровье** (всё необязательно): хронические состояния, лекарства, аллергии, непереносимости,
   травмы и ограничения для тренировок, качество сна, уровень стресса.
6. **Цели** (мультивыбор + свои): избавиться от прыщей, чёрных точек, отёков, лишнего веса; набрать
   мышцы; дисциплина; учёба; деньги; свои цели текстом. Для каждой — приоритет и срок.
7. **Расписание**: школа/вуз; пары с временем и длительностью; **чередование недель** (неделя 1/2,
   переключение вручную); дорога до учёбы; подъём/отбой; работа; выходные.
8. **Питание**: приёмы пищи, предпочтения, что не ест, бюджет на еду, умеет ли готовить, где покупает
   (Пятёрочка и т.д.), сколько воды пьёт сейчас.
9. **Тренировки**: место (дом), инвентарь (нет/есть что), уровень, сколько минут в день, в какие дни.
10. **Финансы**: доходы (стипендия/работа/переводы, даты поступлений), счета (наличка, карты по банкам),
    валюты, крипта (вручную), долги.
11. **Персонаж и голос**: выбор персонажа, голоса, режима мотивации (мягкий/обычный/строгий/жёсткий),
    допустимость мата (по умолчанию нет; редко и только в жёстком режиме, если разрешено).
12. **Разрешения** — по одному, с объяснением зачем: уведомления, движение, геолокация «Всегда»,
    камера, микрофон, медиатека, будильники.

После анкеты ИИ формирует **План**: суточный распорядок, квесты, нормы (вода, калории, БЖУ, сон),
программу тренировок, уход за кожей, курсы обучения — и показывает его как «Системное окно»
с кнопкой «Принять». Пользователь может править.

Повторная оценка: раз в 1–2 недели квест «Контрольное фото» (тело и кожа) → график прогресса
и сравнение «до/после».

## 6. Квесты, баллы, штрафы

- **Квест**: название, категория, время/дедлайн, повтор, подзадачи, награда (◆ баллы, опыт,
  характеристики), штраф, способ подтверждения (кнопка / шаги / фото / таймер / геоточка).
- Виды: ежедневные, из расписания, по цели, **штрафные** (нельзя отменить), **босс недели**,
  квесты знакомства, контрольные.
- **Уровни/опыт/ранги/титулы**: формула опыта в конфиге; характеристики растут от квестов своей категории.
- **Баллы ◆**: за выполнение; списываются за провал. **Можно уйти в минус.**
- **Отказ от квеста**: удержание кнопки 5 секунд → штраф. Сознательный отказ должен быть
  дороже выполнения, но мягче полного игнора.
- **Режим дисциплины** (включается при отрицательном балансе или по выбору ИИ после «срывов»
  вроде отмеченного алкоголя/гулянки):
  подъём 6:00, отбой 22:00, доп. физическая нагрузка, после отбоя блокировка развлекательных
  приложений (§8.6). Выключается, когда баланс снова положительный.
- **Штрафы никогда не трогают здоровье**: нельзя урезать еду ниже безопасной нормы, сокращать сон,
  назначать нагрузку выше уровня пользователя. Штраф — это баллы, доп. задания в пределах плана,
  ограничения развлечений.
- **Пауза**: болезнь/каникулы/отпуск — штрафы не начисляются, серия не сгорает.
- **Магазин наград** (за ◆): награды создаёт пользователь (шоколадка, фастфуд, час игр, вечер без
  квестов…), цена, лимит частоты. При отрицательном балансе магазин закрыт.
- **Вкладка «Магазин» (решение владельца, 2026-10-22)** — отдельная вкладка нижней навигации
  с переключателем: **«За баллы»** — награды за ◆ (как выше); **«Покупки»** — реальные товары
  (продукты, уход, добавки, инвентарь): рекомендации ИИ под план с отметкой по бюджету, ссылки
  на магазины, список покупок (§8.8). В настройках — только параметры маркета (магазины, бюджет).
- Отметки «гулял с друзьями / алкоголь / сорвался» — честная отметка мягче, чем скрытый срыв;
  на следующий день — усиленный план.
- **Награды за уровни (решение владельца, 2026-10-22):** за конкретные уровни — ◆, титулы,
  формы/скины персонажа, открытие новых функций, монстры-боссы. Таблица наград — в конфиге (не в коде).
- **«Путь уровней»:** нажатие на значок LVL на главном экране открывает экран — вертикальная дорога
  уровней в стиле Системы: пройденные / текущий / будущие, у каждого видна награда; текущий подсвечен,
  с прогрессом опыта.

## 7. Напоминания

- Все напоминания по расписанию — **локальные уведомления**, планируются приложением заранее.
- Режим «надоедать»: повтор **каждую минуту**, пока не отмечено «Выполнено». Кнопки прямо
  в уведомлении: Выполнено / +10 мин.
- **Тихие часы**: задаются пользователем, запоминаются.
- iOS держит максимум 64 запланированных уведомления → планировщик держит ближайшее окно
  и перепланирует при каждом открытии и в фоне (BGAppRefresh).
- Звук уведомления может быть **голосом персонажа** (заранее сгенерированный аудиофайл ≤30 с,
  кладётся в Library/Sounds на iOS).
- «Не сделал» к задаче: заранее ставится отложенное уведомление-упрёк на дедлайн+15 мин;
  отменяется при выполнении.

## 8. Разделы

### 8.1 Квесты
Список на сегодня/неделю, история, фильтры по категориям, создание своих квестов, боссы, штрафные.

### 8.2 Питание
- Дневник приёмов пищи: калории и БЖУ, норма от плана.
- Ввод: **штрихкод** (Open Food Facts + своя база на сервере), **вручную с описанием**,
  **фото еды** (ИИ, см. §9.4), «мои рецепты» в один тап.
- Вода: быстрые кнопки +250/+500, норма от веса.
- Список покупок от плана питания с примерной стоимостью.

### 8.3 Тело и здоровье
- Шаги/дистанция/этажи: iOS — CoreMotion, Android — Health Connect / датчик шагов.
- Потраченные калории: базовый обмен (Миффлин–Сан Жеор) + активность + тренировки.
- Сон: время отбоя/подъёма (из отметок и расписания), длительность, влияние на «Энергию».
- Замеры: вес, обхваты, графики. Фото-дневник тела и кожи с сравнением.
- Уход за кожей: утренний/вечерний чек-лист от ИИ под тип кожи, рекомендации средств (§8.8).
- Отёки: акценты на соль/воду/сон, утренний замер лица (фото), тренд.

### 8.4 Тренировки (дома)
- Программа от ИИ под уровень/время/ограничения, прогрессия нагрузки.
- Экран тренировки: упражнение, подходы, таймер отдыха, голосовые подсказки, анимация/схема.
- Опционально подсчёт приседаний/отжиманий через камеру (оценка позы на устройстве).

### 8.5 Прогулки
- Генерация кругового маршрута от текущей точки на N км/минут (iOS MapKit, Android — Google
  Maps/OSM на выбор при реализации).
- Отрезки маршрута с режимами: шаг, ускорение, кардио-интервал, отдых.
- **Голосовые подсказки поверх музыки** («поверни налево и ускорься») с приглушением.
- Работает в фоне с выключенным экраном (геолокация «Всегда»).
- Музыка: Apple Music (now playing + управление), Spotify (SDK App Remote, Client ID в конфиге),
  остальные сервисы — только голос поверх, без названия трека.
- Live Activity с дистанцией/темпом/следующим действием.

### 8.6 Блокировка отвлекающих приложений
- **Android**: по разрешению пользователя (Usage Access + оверлей/Accessibility), список приложений
  (TikTok, YouTube и т.д.), блок после отбоя в режиме дисциплины, экран-заглушка «Система: отбой».
- **iOS**: прямой блокировки нет. Мастер настройки личных автоматизаций в «Командах»:
  «Приложение TikTok открыто → открыть Систему» (deep link `sistema://blocked?app=…`), плюс фокус-режим.
  Приложение при открытии по такой ссылке показывает заглушку и фиксирует попытку.

### 8.7 Финансы
- Счета: наличка и карты (банк, валюта), отдельно. Валюты: RUB (база), TRY, USD, EUR, крипта
  (количество вручную, курс автоматически: ЦБ РФ и CoinGecko через сервер).
- Доходы и расходы по категориям; всё переводится в рубли для отчётов.
- Ввод: вручную; **QR с чека** (данные ФНС, если доступны), **фото чека** (ИИ разбирает позиции);
  из сценария фото еды («купил → сколько стоило»).
- **Android**: чтение уведомлений и SMS банков (по разрешению). Банки выбираются из списка
  (ВТБ, Сбер, Т-Банк, Альфа, Ziraat, İş Bankası, Garanti…); для известных — шаблоны, для прочих —
  разбор дешёвой моделью ИИ.
- **iOS**: импорт выписки (CSV/PDF из банковского приложения, разбор на сервере).
- Лимиты по категориям: ИИ предлагает план после 2–4 недель наблюдений, пользователь подтверждает.
  Превышение → штраф ◆, уложился → награда.
- «Налог на фастфуд» (◆ за покупку вредной еды), цель накопления, подписки, долги с напоминаниями.
- Отчёты неделя/месяц с графиками и комментарием ИИ.
- Вход в приложение по Face ID / отпечатку / PIN.

### 8.8 Маркет покупок
Живёт во вкладке «Магазин» → «Покупки» (решение владельца, 2026-10-22), не в «Ещё»/настройках.
- Подборка товаров под план (уход за кожей, питание, инвентарь): ИИ подбирает → ссылки на
  Ozon, Wildberries, Яндекс Маркет, Пятёрочку, Trendyol (TR).
- Цена — примерная (через веб-поиск на сервере), с датой и источником; ссылка на товар или поиск.
- Пометка по финансам: «можно купить», «после поступления денег», «не по бюджету».

### 8.9 Знания
- «Хочу выучить X» (что угодно: от нунчак до C++) → ИИ строит курс: модули, ежедневные уроки,
  практика, проверочные вопросы, квесты с опытом в «Интеллект».
- Интервальные повторения, прогресс по курсу.

### 8.10 Подключения (последний этап)
Раздел «Подключения» с кнопками «Добавить …». Первым — расписание/дневник **МИРЭА** (через их
веб/приложение, способ выяснить при реализации). Каждое подключение — отдельный модуль.

### 8.11 Будильник-квест
Будильник (AlarmKit на iOS, AlarmManager на Android), который отключается только выполнением
задания: N приседаний (камера/датчики) или скан QR-кода в другой комнате. Фолбэк на iOS, если
AlarmKit недоступен: серия громких уведомлений.

### 8.12 Виджеты и Live Activity
- Виджет: следующий квест + таймер, шаги, вода (кнопка +250 через App Intent).
- Экран блокировки: уровень, баллы, следующий квест.
- Live Activity: активный квест с таймером, прогулка, тренировка.

### 8.13 Режимы дня
- **Автоплан**: экран показывает только одно текущее задание. Пока оно не выполнено (или не отказано
  удержанием 5 сек со штрафом), следующее задание на сегодня не открывается. Включается в настройках
  или по выбору ИИ в режиме дисциплины.
- **Занятость**: отметка «занят» (пары, работа, дорога, вручную на N часов) — квесты и напоминания
  в это время сдвигаются, а не штрафуются; тихие уведомления.
- **Адаптивная сложность**: по успеваемости за 7–14 дней (процент выполнения, серии, провалы)
  нагрузка, количество квестов и нормы плавно растут или снижаются. Шаг изменения ограничен,
  никогда выше безопасных рамок плана.
- **Итоги дня**: перед отбоем ассистент голосом и текстом подводит итоги (что сделано, баллы,
  ошибки, план на завтра).

### 8.14 Внешность (лукс-макс) и уход
- Раздел с планом улучшения внешности: кожа, отёки, осанка, сон, вес, стрижка/брови/уход за
  волосами, стиль одежды, гигиена, мьюинг/осанка языка, упражнения для шеи и осанки.
- **Асимметрия лица**: оценка по фото анфас (ориентиры глаз, бровей, губ, челюсти) с пометкой
  «оценка», трекинг во времени; советы только безопасные (осанка, привычки сна на одной стороне,
  жевание на обе стороны, уход) и рекомендация к специалисту при выраженной асимметрии.
- Методы: **умывание холодной водой / льдом** (утренний квест против отёков, с ограничением по
  времени и предупреждением при чувствительной коже/розацеа).
- **Запрещено предлагать**: «bone smashing» и любое травмирование лица, гормоны/стероиды/пептиды
  без врача, препараты для похудения, экстремальные диеты и голодание, опасные для здоровья методы.

### 8.15 Пищевые добавки
- Список своих добавок, расписание приёма (квесты + напоминания), остаток упаковки и напоминание о покупке.
- ИИ даёт общую информацию о добавках под цели (витамин D, омега-3 и т.п.) и предупреждает о
  известных взаимодействиях с лекарствами из анкеты. Дозировки — только по этикетке; при
  лекарствах и хронических состояниях — совет согласовать с врачом. Никаких рецептурных препаратов.

### 8.16 Баня
- Отдельный день недели для бани (настраивается) как квест: длительность заходов, перерывы, вода.
- Предупреждения: не после алкоголя, при плохом самочувствии, давлении, сердечных проблемах из анкеты.
- Можно пригласить друзей (§8.18).

### 8.17 Вредные привычки
- Трекер привычек, от которых избавляешься (курение, вейп, сладкое, энергетики, залипание в телефон,
  поздний отбой и т.д.): счётчик дней без, срывы, триггеры, экономия денег (связь с финансами).
- Награды за серии, мягкий штраф за срыв (честная отметка дешевле скрытой).
- При зависимостях — ненавязчивая ссылка на профессиональную помощь.

### 8.18 Друзья и рейтинг
- Добавление друзей по коду/ссылке, профиль друга (уровень, ранг, титулы — только то, что он открыл).
- **Совместные квесты**: общая цель (шаги, тренировка, баня, прогулка), прогресс каждого, общая награда.
- **Рейтинг**: топ среди друзей за неделю/месяц/всё время (опыт, шаги, серии). Глобальный топ —
  только если пользователь включит.
- Приватность: фото, вес, здоровье, финансы друзьям **никогда** не показываются. Каждый пункт
  профиля скрывается отдельно.
- Требует серверных аккаунтов и многопользовательской модели (§10).

### 8.19 Охота на монстров (мини-игра)
- Раз в неделю (и как награда за забеги) — «Охота»: Система называет точку на маршруте забега/прогулки.
- По прибытии (геозона) — уведомление, открывается камера, поверх изображения появляется монстр
  (2D/3D-модель, AR без сложного трекинга достаточно: привязка к центру экрана + лёгкое движение
  по гироскопу).
- Поимка: быстро нажимать по экрану; нужное число нажатий и время зависят от редкости/силы монстра
  (E→S), полоса «сопротивления» монстра убывает.
- Награда: ◆, опыт, редкие титулы; **коллекция пойманных монстров** (бестиарий).
- Все монстры — оригинальные. Ассеты подключаемые; на старте — заглушки.
- Безопасность: монстр не появляется, пока человек движется быстро/пересекает дорогу; подсказка
  «остановись, прежде чем смотреть в экран».

### 8.20 Музыка под задание
- Плейлисты под тип задания: бег/кардио (по темпу шагов, BPM), силовая, учёба/фокус, отбой.
- Apple Music и Spotify: приложение подбирает и запускает плейлист из библиотеки/каталога сервиса
  (через их API), остальные сервисы — ссылка на плейлист.

## 9. ИИ

### 9.1 Архитектура
- Все запросы к ИИ идут **только через сервер**. Ключи — только на сервере.
- Слой провайдеров: единый интерфейс, модель для каждой задачи задаётся в конфиге
  (`server/config/ai.yaml`), ключи — только в `.env` на сервере. Два ключа: Anthropic и Google.
  Модели по умолчанию:

  | Задача | Модель |
  |---|---|
  | Персонаж: разговоры, реплики с характером | `claude-opus-5-5` |
  | Аналитик дня, разбор недели, оценка прогресса | `claude-opus-5-5` |
  | Фото тела и кожи (оценки, асимметрия, сравнение) | `claude-fable-5-1` |
  | Сообщения наперёд, планы, курсы и уроки | `claude-sonnet-5-5` |
  | Фото еды и чеков + поиск КБЖУ | `gemini-4-argon` |
  | Короткие шаблонные реплики, разбор уведомлений банков | `claude-haiku-5-5` |

- **Две роли ИИ**:
  - **Аналитик** — без отыгрыша, возвращает строгий JSON (цифры, выводы, рекомендации, предлагаемые
    изменения плана). Результаты сохраняются как данные (графики, история, до/после).
  - **Персонаж** — получает выводы аналитика и пересказывает их в своём характере. Никогда не
    искажает цифры и факты ради роли.
- **Карточки персонажей** (`server/config/characters/<id>.yaml`): характер, манера речи, словечки,
  что можно/нельзя, отношение к пользователю, отдельно для каждой формы, и 15–25 примеров реплик
  по ситуациям (утро, похвала, провал, срыв, отказ от квеста, усталость, вечерние итоги, вопрос
  не по теме). Режим мотивации накладывается поверх карточки.
- **Слепой тест моделей** (`server/cmd/aibench`): набор из ~20 ситуаций для роли и 15–20 фото еды
  с реальными граммами; прогон через 3–4 модели, страница сравнения без названий моделей,
  пользователь выбирает лучшие — результат записывается в `ai.yaml`.
- Кэширование промптов (карточка персонажа, профиль, план) для экономии.
- **Бюджет $27/мес**: учёт токенов и стоимости по каждому вызову (по задачам), дневной/месячный лимит.
  При приближении к лимиту: персонаж → `claude-sonnet-5-5`, аналитик дня → Sonnet; фото тела
  и кожи → Opus. Экран статистики расходов в настройках. Цены моделей — в конфиге, не в коде.
- Пока ключей нет (провайдер ещё не подключён) — ИИ-функции работают на шаблонах, без ошибок.
- Расчёты (калории, баллы, баланс, деньги) делает **код**, не ИИ.
- ИИ имеет **инструменты** (tool use) для изменения состояния: создать/изменить квест,
  начислить/списать ◆, поменять норму, добавить штрафной квест, записать еду. Каждое действие ИИ
  логируется и видно пользователю («Система изменила план: …»), с возможностью отменить.

### 9.2 Персонаж
- **Живёт поверх всех экранов** (глобальный оверлей): ходит вдоль низа экрана, останавливается,
  садится, реагирует на события (выполнил квест — радость; провал — злость/разочарование;
  долго нет активности — подходит и говорит). Не мешает нажимать на интерфейс (можно убрать
  в «карман» свайпом).
- **Касания (решение владельца, 2026-10-22):** обычный тап **не открывает чат** — персонаж реагирует
  и говорит короткую реплику (облачко + голос). **Удержание 3 секунды** (индикатор заполнения вокруг
  персонажа) — режим **живого общения с ИИ**: голосовой разговор без кнопок (говоришь — он отвечает
  голосом и снова слушает) с текстовой лентой; выход — кнопкой или жестом. Текстовый чат доступен
  из этого режима.
- Реплики появляются в облачке над ним + озвучиваются голосом.
- **Свободное перемещение по всему экрану**, а не анимация на месте: персонаж реально ходит/бегает
  по экрану в любом направлении, по траектории (поиск пути в обход интерактивных элементов),
  с плавным разворотом в сторону движения и правильным масштабом/перспективой.
  - «Мир» персонажа — текущий экран: края панелей и карточек считаются поверхностями, на которые
    можно запрыгнуть, сесть на край, облокотиться, спрыгнуть вниз; при прокрутке он держится
    за свою поверхность или спрыгивает.
  - Целенаправленное поведение: подходит к нужному элементу и показывает на него (кнопка квеста,
    шкала воды), идёт к пользователю (к низу экрана) когда говорит, уходит в угол, когда мешает.
  - Автономное поведение в простое: бродит, садится, осматривается, засыпает ночью; случайные
    короткие действия (прыжок, потягивание, взмах) — как добавка, не замена ходьбы.
  - Перетаскивание пальцем (берёшь и переносишь, он реагирует), свайп — спрятать в «карман».
  - Не перекрывает текущую кнопку/поле ввода: обходит или временно становится полупрозрачным.
  - Производительность: 60 fps, пауза анимации при «Уменьшении движения» и в фоне, лимит по батарее.
- Анимации: набор состояний idle, walk, run, jump, climb, sit, sleep, talk, happy, angry, point, wave,
  fall, drag. Скорость шага синхронизирована с перемещением (без «скольжения» ног).
- **Модели присылает пользователь.** Поддержать загрузку без переделки кода:
  - 3D: **glTF/GLB** и **VRM** (аниме-модели) с анимационными клипами или ретаргетингом на общий набор;
  - 2D: **Rive**, **Spine** или спрайт-листы;
  - папка `app/assets/characters/<id>/` + `character.json` (имя, формат, масштаб, точка опоры, карта
    состояний → клипы, голос, характер). Пока моделей нет — заглушка-силуэт.
  - Если модель пришла без нужного клипа — фолбэк на ближайший (нет run → ускоренный walk).
- **Формы персонажа**: у одного персонажа может быть несколько моделей-форм (базовая, усиленная и т.д.),
  каждая со своим условием в `character.json`, например `{"form":"rage","model":"rage.glb","unlock":{"streak_days":7}}`.
  - Условия: серия дней, уровень, ранг, босс недели, режим дисциплины и т.п. (расширяемо).
  - Усиленная форма активна, пока условие выполняется; при потере (сорвал серию) персонаж
    возвращается в базовую форму.
  - Смена формы — отдельная анимация-событие (вспышка/трансформация) + системное окно
    «[ Уведомление ] Форма разблокирована» / «Форма утрачена»; у формы может быть свой голос и манера речи.
  - Пока условие не выполнено, форма видна в профиле персонажа как заблокированная с прогрессом
    («серия 4/7»).
  - **Личные модели не попадают в репозиторий** (он публичный): папка `app/assets/characters_private/`
    в `.gitignore`; в репо — только заглушка и пример `character.json`. CI собирает с заглушкой,
    для личной сборки с моделями — локальный скрипт `tools/build_private` (Android-сборка локально;
    для iOS — инструкция, как подложить модели в сборку без коммита).
  - Модели оптимизировать для телефона: до ~50k треугольников, текстуры ≤2K, сжатие (Draco/KTX2,
    если поддерживается рендером).
- **Решение владельца (сохраняется):** на старте — оригинальные персонажи, нарисованные векторно в коде,
  со всеми состояниями. Присланные модели (GLB/VRM, Rive/Spine/спрайты) подключаются позже через тот же
  единый интерфейс отрисовки, без переделки кода. Пока моделей нет — показываются векторные персонажи;
  заглушка-силуэт — только для формы, у которой нет ни модели, ни векторного варианта.
- При выборе персонажа видно самого персонажа в движении (все состояния) и можно **прослушать голос**.
  До подключения TTS-провайдера (§9.3) — системный синтез речи телефона (ru/tr), у каждого персонажа свой
  тембр/скорость; он же остаётся офлайн-запасным.
- Персонажи **только оригинальные** (никаких существующих аниме-персонажей). Архетипы на старте:
  аниме-девушка, аниме-парень, «невозмутимый силач», «мрачный мечник». Каждый — характер,
  манера речи, голос. Пользователь выбирает и может сменить.
- Режимы мотивации: мягкий, обычный, строгий, жёсткий. В жёстком — ругает «по всей строгости»,
  но без унижения внешности/здоровья и без опасных советов.
- Android: опционально персонаж поверх других приложений (разрешение оверлея).

### 9.3 Общение
- Чат текстом и голосом (распознавание речи на устройстве: ru/tr; кнопка микрофона/удержание).
- Голос персонажа: TTS-провайдер с библиотекой готовых голосов (ElevenLabs или аналог), голос
  выбирается в настройках. Клонирование голосов реальных людей — запрещено.
- Контекст: профиль, план, сегодняшние квесты, история выполнения, финансы, последние сообщения.
- Пример сценария: «Пора выпить воды» → «у меня нет воды» → персонаж находит ближайший магазин
  (поиск мест + маршрут) и предлагает дойти (квест-прогулка).

### 9.4 Фото
- **Еда**: ИИ описывает, что видит → спрашивает «купил или приготовил?».
  Купил → «где?» → сервер ищет КБЖУ этого блюда/товара (веб-поиск модели), показывает с источником;
  есть упаковка — предлагает отсканировать штрихкод. Приготовил → ИИ оценивает по фото, можно
  уточнить ингредиенты/граммы; блюдо сохраняется в «мои рецепты». Найденное кэшируется на сервере.
  Цена покупки → в финансы.
- **Тело и кожа** (онбординг и контрольные фото): оценки с диапазоном и пометкой «оценка», сравнение
  с прошлыми фото.
- **Чеки**: позиции, суммы, магазин → в финансы.

### 9.5 Сообщения ИИ без серверного push
iOS не принимает push с сервера (бесплатный Apple ID), поэтому:
1. При открытии приложения и в фоне (BGAppRefresh) клиент забирает с сервера **пачку сообщений
   на ближайшие часы** (утренний брифинг, подбадривания, заранее написанные упрёки на случай
   пропуска каждой задачи, аудио) и ставит их локальными уведомлениями.
2. Упрёк за пропуск задачи ставится на дедлайн+15 мин и отменяется при выполнении.
3. Если запас кончился (долго не открывал) — работают шаблонные реплики, записанные заранее.
4. Запасной канал (выключен по умолчанию, интерфейс уже есть): **ntfy** на сервере.
   Android: FCM push работает штатно.

## 10. Сервер

### API
- REST/JSON, версионирование `/api/v1`. OpenAPI-описание в репозитории.
- Аутентификация: **имя + пароль** (argon2id) + **TOTP** (настройка через QR в приложении).
  Сброс пароля — только по TOTP-коду. Access-токен (короткий) + refresh-токен (в Keychain/Keystore).
- Ограничение частоты запросов, особенно на вход.

### Синхронизация (офлайн-first)
- У каждой записи: `id` (UUID, генерирует клиент), `updated_at`, `deleted_at`, `device_id`, `version`.
- Клиент пишет в локальную БД и складывает изменения в очередь; синхронизация: push изменений →
  pull изменений с момента последней синхронизации. Конфликты: last-write-wins по полю, кроме
  баллов/опыта — они считаются из журнала событий (event log), а не перезаписываются.

### Хранилище
- Фото: `/opt/sistema/data/photos/<user>/<yyyy>/<mm>/`, сжатие (WebP, ~1600px длинная сторона,
  оригинал не храним), миниатюры. Отдача только авторизованному владельцу.
- **Обработка фото строго по очереди** (один воркер, без параллельного декодирования), лимит размера
  загрузки, стриминг на диск: декодирование большого снимка кратковременно ест ~100–150 МБ, а RAM 1 ГБ.
- База продуктов (своя, пополняется), кэш КБЖУ блюд, кэш цен товаров, курсы валют.
- **Бэкапы**: ежедневно SQLite (online backup API) + фото (инкрементально) в отдельную папку/диск,
  хранить 14 дней; скрипт восстановления и проверка в README.

### Фоновые задачи
Планировщик внутри процесса: генерация сообщений наперёд, недельный анализ, курсы валют,
обновление цен, бэкапы, очистка.

### Деплой
- `deploy/`: systemd-юнит, `.env.example`, скрипт установки (создание пользователя, папок, юнита),
  инструкция HTTPS. Скрипт **не трогает** чужие сервисы, порты и конфиги.
- Перед установкой скрипт проверяет `free -h` и занятые порты и печатает отчёт. Если доступной
  памяти < 300 МБ и swap нет — предлагает (с подтверждением пользователя) создать swap-файл 2 ГБ.
  systemd-юнит с `MemoryMax=300M`, чтобы сервис не мог положить остальные.
- Метрики: `/healthz`, лог в journald, потребление памяти в логах.

## 13. Правила работы для Claude Code
- Сначала читай `SPEC.md`, затем свой этап в `STAGES.md`. Делай только текущий этап.
- Репозиторий-монорепо: `app/` (Flutter), `server/` (Go), `deploy/`, `docs/`, `.github/workflows/`.
- Mac нет: каждое изменение проверяется сборкой в CI. После пуша — `gh run watch`; при падении —
  `gh run view --log-failed`, исправить, повторить (до 8 итераций), затем остановиться и показать ошибку.
- Тесты: юнит-тесты на логику (баллы, штрафы, калории, синхронизация, расписание с чередованием
  недель); `go test` для сервера; виджет-тесты на ключевые экраны.
- Параллельная работа: используй сабагентов для независимых частей с чёткими границами файлов;
  общие файлы (pubspec.yaml, роутер, схема БД, Info.plist, AndroidManifest, entitlements) правит
  только главный агент.
- Секреты не коммитить. Не выдумывать API сторонних сервисов: если не уверен — оставь интерфейс,
  заглушку и TODO с объяснением.
- В конце этапа: короткий отчёт (что сделано, что не проверено, что нужно от пользователя) и
  ссылка на собранные .ipa/.apk.
