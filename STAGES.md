# STAGES — этапы и промпты

Как пользоваться: положи `SPEC.md` и `STAGES.md` в корень репозитория. Для каждого этапа открой
новую сессию Claude Code и вставь текст блока «Промпт». Следующий этап начинай, когда текущий
собран, установлен на телефон и проверен.

## Порядок работы на каждом этапе (обязательно)

1. **Каркас (главный агент, сам):** общие файлы — `pubspec.yaml`, `go.mod`, схема БД (Drift/SQLite),
   роутер, модели и интерфейсы сервисов, Info.plist, AndroidManifest, entitlements, CI. Закоммить.
2. **Параллельно — сабагенты (Task tool)** по разбиению из блока «Сабагенты» этапа. Правила:
   - у каждого сабагента своя папка/файлы, чужие не трогает;
   - общие файлы (п. 1) правит **только главный агент**; сабагент перечисляет нужные изменения
     (зависимости, ключи Info.plist/манифеста, поля БД, маршруты) в итоговом отчёте;
   - сабагенты не коммитят; каждый возвращает: список файлов, нужные изменения общих файлов,
     риски компиляции, что не проверено;
   - сабагент пишет юнит-тесты на свою логику.
3. **Интеграция (главный агент):** вносит изменения общих файлов, связывает модули, ревью кода
   целиком, `flutter analyze` / `go vet` в CI, коммит, пуш.
4. **CI до зелёного:** `gh run watch`, при падении `gh run view --log-failed` → исправить → пуш,
   до 8 итераций, затем остановиться и показать ошибку.
5. **Отчёт** и ссылки на .ipa/.apk.
